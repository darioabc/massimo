# Changelog

## 0.2.0

Extract a full design system from an existing repo, in the W3C Design Tokens format 2025.10. After updating, run `init.mjs --update-scripts`, rebuild the tokens once, and run `tokens.mjs migrate` when you want the new format.

### Added

- `/massimo:extract`: a full design system from an existing repo in one guided flow. Tokens for every family from what the repo already uses, each primitive's props, variants, states and usage rule, and a design-system README, approved family by family. It records progress against the graph, tokens and guard phases. `/massimo:start` offers it for a repo with styling but no token set.
- Readers for every place an existing repo keeps design values (`scripts/lib/readers.mjs`): CSS custom properties, now with `light-dark()` split into light and dark and RGB or HSL channel triplets (`236 229 209`, `210 40% 98%`) typed as colours that keep their channels as CSS; a Tailwind 3 config (`theme` and `theme.extend`, `DEFAULT` as `$root`, `rgb(var(--x) / <alpha-value>)` as a reference, font-size tuples as type steps); a CSS-in-JS or JS theme object (MUI, Chakra, Stitches, vanilla-extract and plain exports); Tokens Studio files; and Figma variables exported as JSON, from the REST API or from `read-library.js`. Custom properties go in families by the names systems use (`--space-*`, `--c-*`, `--dur-*`, `--z-*`), colours by their value, and a stem with a size and a line height, weight or tracking (`--h1-size`, `--h1-leading`) becomes a type step. `rgb(var(--x))` over a channel triplet is a reference that keeps its wrapper as CSS, `rgb(var(--x) / 0.14)` is the colour it makes in each theme, and a fluid `clamp()` size holds its largest value with the clamp kept. JavaScript is read as text by a small object-literal reader and never run, so a config reads without its packages installed; anything computed or spread is named in a note instead of guessed.
- The colour parser knows all 148 CSS named colours (24 before), computes `color-mix()` in sRGB, linear sRGB, OKLab and OKLCH, and reads `light-dark()`.
- The audit counts an inventory of the families a token set needs beyond its findings: line heights, letter spacing, font weights, shadows, borders, durations, easings, z-index and opacity, from CSS, JS style objects and Tailwind classes. It also says what each colour cluster is used for (background, text, border, fill, shadow). Neither joins the ratchet, so existing baselines do not move.
- `tokens.mjs extract` proposes a full token set from what the repo already uses. Its sources come first (CSS custom properties, `tokens.tailwindConfig`, `tokens.themeFiles`, `tokens.importFiles`, `tokens.figmaExport`, which `detect` now suggests), with `var(--x)` turned into references between them. Two names for one CSS variable (a Tailwind config's `base.100` and a stylesheet's `--color-base-100`) are one token, and a token whose name another source uses as a group takes its own variable's name, so nothing is lost. The audit then fills the gaps with values the code uses at least twice: colour ramps named by lightness, with in-between steps (`435`) when the nearest is taken, translucent colours as overlays named by their base (`black-12`, `blue-20`), shadow colours left in their shadows, and colours only ever found in data (an avatar palette) left out; semantic background, text and border colours from where colours are used, neutral first, with a coloured background as the accent; spacing on the detected grid, radii, font families, weights and sizes named around the body size, or by Tailwind's names in a Tailwind repo. Where the sources already define three or more steps of a scale, the code's other values are drift for the tidy phase, not new steps; typography composites (exact from a type step in a Tailwind config or a stylesheet, otherwise from the most used parts, with every assumption said; body text never takes `leading-none`, and a Tailwind size takes Tailwind's line height); shadows, borders, durations, easings, z-index and opacity. Every semantic token gets a drafted `$description`, and contrast pairs are marked by name (`base-content` on `base-100`, `content` on its group's `100`) or by role. `tokens/draft/report.md` lists each token with its value and where it came from, family by family, and each value it did not propose with the reason.
- The graph lists each component's props (TypeScript types, Vue's `defineProps`, Svelte 4 and 5 props, Astro `Props`, `cva` and `tv` variants) with values and defaults, how call sites set each one, and the states it styles (hover, focus, disabled, ARIA and data attributes, state props).
- New `docs.mjs` writes the design system's README for a person or an agent to read first, between `massimo:docs` markers so the team's own sections stay; `--check` joins `ds:check`.
- The graph and the audit read the token set in either format.

### Changed

- Tokens are written in the W3C Design Tokens format 2025.10. A resolver document (`tokens/tokens.resolver.json`, `"version": "2025.10"`) ties `base.tokens.json` to one file per theme (`theme/dark.tokens.json`); colours are colour objects in their own colour space, sizes and durations are `{ value, unit }`, typography, shadow, border, transition, gradient and stroke style are composites, and every token has an explicit or inherited `$type`, never a guess. massimo reads `$root`, `$extends`, `$ref` and `$deprecated`, keeps other tools' `$extensions`, and checks every value against its type. Each file it writes carries `$extensions.massimo.format: 2`, and a newer format or resolver version is refused with "update massimo". A `tokens.json` from before 0.2.0 still builds exactly as before.
- New `tokens.mjs migrate` converts a `tokens.json` from before 0.2.0 to 2025.10 (and `--to legacy` back), writes `migration-report.md` with anything that did not carry over exactly, checks that every output builds the same, and points the config at the new files. It refuses while the vendored scripts are older than it. A value the spec has no type for (`clamp()`, a grid template) moves to `$extensions.massimo.cssOnly` and still reaches the CSS outputs; a length in em keeps its exact CSS beside the nearest px value.
- `tokens.mjs extract` writes a 2025.10 draft in `tokens/draft/`, with a report of any value it typed or could not convert exactly.
- Contrast pairs name their use (`$extensions.massimo.contrast: { on, use }`), which sets the WCAG 2.2 minimum: text 4.5:1, large text 3:1, UI and focus 3:1. `tokens.mjs check` reports each failure under its theme. An old `on` plus `contrast` pair still works.
- Tailwind outputs map font weights, easings, `space`, `radii` and `$root` tokens; Tailwind 3 also gets durations, z-index and opacity. The JSON output carries `deprecated`.
- Figma: `figma-variables.json` gives every variable its scopes (by type and name; a colour ramp's steps hide once semantic colours exist, nothing is left on all scopes), durations in ms, and one font family per font variable. Typography tokens become text styles and shadow tokens effect styles, each field bound to the variable its part points at. Easings, transitions, gradients, borders and CSS-only values are listed under `notMirrored` instead of becoming strings.
- New `tokens.mjs figma --record <export.json>` and `--drift <export.json>`. The export is what `skills/figma/read-library.js` returns from one read-only `use_figma` call: every variable in every mode with aliases, and the text and effect styles. Recording checks the file against code, names each mismatch and writes `figma/mirror.json` with each variable's id and mirrored values. Drift compares code, the mirror and Figma, and writes `figma/drift.md` with each change put down to code, Figma or both. The hash now covers every file a resolver names.
- The figma skill uses that script instead of `get_variable_defs`, which reads one node and sees neither modes nor aliases. On a file that allows one mode per collection (Figma's Starter plan), it mirrors the default theme only and says the others stay in code. (`figma-create-new-file`, flagged in the review, is a real skill in Figma's plugin; it is now loaded before `create_new_file`.)
- New output format `designmd`: Google Labs' DESIGN.md for coding agents, pinned to format version alpha as published in release 0.4.0 (2026-07-27). The front matter holds the default theme's colours (references between colours kept), typography, radii and spacing; the prose holds descriptions, contrast pairs, shadows, and each component's `ds:use-when` and `ds:never` rules from the graph, in the order the spec sets. The format has no themes, so the file names the other themes and says they live in code. A colour DESIGN.md cannot read (`color()`, a `none` component) is written as its nearest sRGB hex and listed. Checked once with `@google/design.md` 0.4.0's linter: no errors.
- After updating, run `npm run ds:tokens` once and commit: every generated file has a new header, so `ds:check` reports them stale until rebuilt.
- `reviewer` and `visual-reviewer` declare `tools: Read, Grep, Glob, WebSearch, WebFetch`, so they cannot write or run commands. They no longer drive a browser: the ux skill captures each viewport and state (screenshots plus a page snapshot from the new `shoot.mjs --dom`) before it dispatches them.
- `ideator` declares `tools: Read, Grep, Glob, Write, WebSearch, WebFetch`, and a new PreToolUse hook (`scripts/agent-guard.mjs`) refuses its writes outside `<project>/explorations/`. The orchestrator now renders each direction and sends back broken ones.

### Fixed

- The kit and the token preview show an alias's value in every mode. Before, a token that pointed at another kept its default value in dark mode when only its target changed.
- Colour objects in any DTCG colour space become CSS (`oklch()`, `hsl()`, `color(display-p3 …)` and the rest), and every composite type becomes real CSS: typography (the `font` shorthand plus a variable per part), shadow (one or several, with `inset`), border, transition, gradient and stroke style. References inside a composite stay linked as `var()`. Before, composites came out as `[object Object]` and most colour objects as raw JSON.
- Mode blocks follow `tokens.darkSelector`: with `.dark`, a `brand` mode uses `.brand` and the media query opts out of `.light`. New `tokens.defaultMode` names the default mode (Figma's first mode) and `tokens.selectors` sets any mode's selector. The kit follows the same selectors and `darkMedia`, and still answers to `data-theme` for the canvas. A mode named `default`, or named like the default mode, is an error.
- Two tokens that map to the same CSS variable are an error naming both.
- Figma variables: `em` lengths stay strings instead of becoming rem times 16, an alias names the collection it points into, and each collection carries only the modes its own variables change in.
- Token files are checked before anything is written, and every problem is reported in one run with its token path: names with `{`, `}` or `.`, a token that is also a group, a `cssVar` that is not a custom property name, and any string that could break out of a CSS declaration (`;`, braces, angle brackets, unclosed quotes or brackets). Names with other odd characters become safe CSS variable names. Comments, JS keys, family names and the preview's inlined kit are escaped for where they land.
- JSONC reading drops trailing commas only outside strings.
- `state.json` and `STATUS.md` are written through a temporary file and renamed into place, with ISO timestamps. `state.mjs set`, `explore` and `decide` take a lock, so two sessions at once both keep their change. `init` adds `.gitattributes` with `decisions.md merge=union`.
- New `tokens.mjs hash` hashes the tokens as canonical JSON, so reformatting is not drift, and `tokens.mjs check` reports when the Figma mirror was recorded from other tokens. Mirrors recorded before 0.2.0 still count.
- The canvas frames every mockup in a sandbox, runs a mockup's script only when its direction sets `"scripts": true`, reads direction files only from their own round folder, and inlines the kit as text.
- `serve.mjs` answers a malformed URL with 400 instead of crashing, and refuses a symlink that leads out of the folder.
- `tokens.mjs kit` works on a project with no tokens yet, so the design loop can start on a blank project.
- Nothing hard-codes `design-system/` any more: skills, agents and references write `<project>/` (the configured `projectDir`), the token source defaults to `<projectDir>/tokens/tokens.json`, and generated headers and messages name the real folder. Generated headers say "Generated by massimo" in plain text.
- `detect` adapts the audit's globs to a repo with no `src/` folder, so the audit no longer finds nothing there.
- `init` says how to run the scripts in a repo with no `package.json`, and the README says so too.
- A new project's STATUS.md no longer names the graph as the next step before the phases are chosen.
- The ux loop records the pick, and sets the `reviewing` and `fidelity` statuses. STATUS.md and the session hook agree that an exploration is open until its handoff is written or it is parked.
- Screenshots that a handoff, brief or baseline links to go in `shots/kept/`, which is committed, so teammates do not see dead links. `init` warns a project whose `.gitignore` still ignores all of `shots/`.
- The README no longer claims a DaisyUI theme output; a DaisyUI app maps its theme names onto the tokens by hand.
- Private leftovers are gone. DaisyUI's component roots and theme names now sit in a registry of class-based component libraries that `graph.classLibraries` can extend; `ticketPattern` is documented. Graph nodes report `style.classes` by library instead of `style.daisy`.
- Sorting no longer depends on the locale, dead code is gone, and the scripts share one set of text helpers (`scripts/lib/text.mjs`).
- The homepage in the manifests points at the README on GitHub.
- `tokens.mjs check` and the preview check contrast for colours kept as channel triplets. Before, those pairs were skipped without a word.
- A colour written in CSS keeps the precision it was written with (`97.807%` is 0.97807, not 0.9781).
- `detect` leaves out a folder with its own `package.json` unless the root declares workspaces, takes the Tailwind version from the dependency before the CSS, counts a JSON file as tokens only with DTCG or Tokens Studio markers, and does not offer a story tool's own stylesheet (`.ladle/`, `.storybook/`) as a token source.

## 0.1.1

- `serve.mjs` renders Markdown as pages: STATUS.md, graph.md, audits, handoffs and briefs open readable in a browser, with a path trail and a Raw link (`?raw` for the file itself).
- A folder with no `index.html` lists its files, with its STATUS.md or README.md rendered under the list, so `npm run ds:serve` opens on the project's status.
- New zero-dependency Markdown renderer (`scripts/lib/markdown.mjs`), vendored with the other scripts. Run `init.mjs --update-scripts` to pick it up in a repo.

## 0.1.0

First release.

- Skills: start, status, graph, stories, tokens, tidy, guard, ux, figma.
- Agents: baseline, reviewer, visual-reviewer, ideator, translator, story-writer, tidy-worker.
- Scripts (zero-dependency, vendored into the repo): detect, init, state, graph, audit, tokens, canvas, serve, shoot, session-start.
- Story-lane recipes: Vite (React, Preact, Vue, Svelte, Solid), Next.js, Astro, SvelteKit, Nuxt, other.
- SessionStart hook that tells a new session where the project stands.
- Graph: tiers and groups from `ds:group`, `ds:no-story`, header faults, a story queue by usage, and `graph.extraKeys` for a repo's own `ds:` keys.
- Audit: colours, arbitrary values, lengths, font families, primitive reads, undefined `var()` reads and Tailwind palette keys, with a per-offender ratchet (`--baseline`, `--lower`, `--check`). Style files are audited too, except their token declarations.
- Tokens: W3C DTCG source with modes and contrast pairs, built into CSS, Tailwind 4, Tailwind 3, SCSS, JSON, TS, Figma variables and the mockup kit; a visual preview page.
