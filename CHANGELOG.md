# Changelog

## 0.4.1

Fixes from running massimo on public repos it had never seen, among them Nuxt 3 and 4 apps, monorepos, a Capacitor app and repos that keep Storybook. After updating, run `init.mjs --update-scripts`, then `adopt.mjs scan` before the next `plan`, and rebuild the token outputs (`tokens.mjs build`): in a Tailwind 3 project the tailwind3 output writes colours in a new form. No file format changes: the inventory gains a few fields (`widths` on a story file that sets `meta.width`, and Ladle's `previewPort` and `notLiteral`) that older scripts ignore.

### Added

- The graph reads a Nuxt app. Nuxt's aliases (`~`, `@`, `~~`, `@@`, `#shared`, `#layers/<name>` and the `alias` option) resolve, with `~` and `@` inside a layer pointing at that layer. A template tag, a `resolveComponent()` call or an import from `#components` that names a component Nuxt auto-imports counts as a use, by Nuxt's own naming rule, and shadcn-nuxt's component folder is included. The folders under `layers/` that hold a `nuxt.config` and the local paths in `extends` are read in Nuxt's own layer order; a remote or package layer is listed as a warning. `graph.edges: ["!nuxt"]` turns the auto-import edges off and keeps the aliases. `scripts/lib/nuxt.mjs` ports Nuxt 4.6.4's component naming rule, scule's case splitting and shadcn-nuxt 2.9.0's component registration, and carries their MIT notices.
- detect suggests every components folder a Nuxt app registers as `components.include`, each layer's included.
- Keeping Storybook: a repo that keeps Storybook gets its stories keys proposed by detect and by adopt plan. `stories.include` comes from the stories list in `.storybook/main`, and `devCommand`, `port`, `url` and `storyUrl` (Storybook's iframe URL with `{id}`) from its `storybook dev` script; what massimo cannot read is a note. The start skill recommends skipping adopt, with a recorded reason, when a kept story tool is all there is to adopt, and plan says the stories stay in the tool.
- `stories.mjs storybook [<file>...]` names each story's Storybook id and URL by Storybook's own rule, ported from Storybook with its MIT notice, without running Storybook, for story files or for a component's stories. `--routes` writes a sweep routes file, and `--against <url>` checks the ids against a running Storybook's index.
- The stories, ux, tidy and Figma skills and the story agents write new stories as CSF files beside a kept Storybook's, and open them at its iframe URLs, shot with `--selector '#storybook-root'`.

### Changed

- Every script's file list leaves out what git ignores, as `git ls-files` does, so a build, or Capacitor's copy of the web build inside `android/` or `ios/`, is never read as source. The audit still reads ignored files for the custom properties they define.
- In a Tailwind 3 project, the tailwind3 output writes each opaque colour as `rgb(var(--x-rgb) / <alpha-value>)`, and the css output declares its channels in every theme, so opacity modifiers such as `bg-brand-500/50` keep working. oklch(), lab() and display-p3 colours stay `var()`.
- Tailwind palette classes: before the repo has colour tokens, `latest.md` counts the palette classes the code uses. Once it has, a palette class whose colour a default-theme token holds is a finding that names that token as its fix, and the others are counted in `latest.md` and `latest.json`, never in the baseline. A config that replaces Tailwind's palette (`theme.colors`, or `--color-*: initial`) skips the palette kind.
- An import that starts with `@/` or `~/` and resolves to nothing is listed as unresolved, in any project, instead of as a package.
- `tokens.mjs check` says how many contrast pairs it checked when none fails (`0 contrast failures in 12 pairs`), and says plainly when it checked none, where it used to print `0 contrast failures` either way.
- The audit skips `primitive-read`, with the reason in `latest.md`, against a token set where no token aliases another, so adopting a flat draft no longer flags every read of the repo's own variables. Baseline entries of that kind are not checked until the set gains an alias.
- init warns, and writes nothing, when the repo checks its formatting and its ignore patterns leave in the project folder or `massimo.config.json`. For prettier it names the lines to add to `.prettierignore`; for a format check in CI by Biome, dprint or oxfmt, it names the tool and the config that holds its ignore patterns.

## 0.4.0

A csf story lane for repos whose stories are CSF files, with a converter and proof against the tool it replaces. After updating, run `init.mjs --update-scripts`. A project that sets no 0.4.0 key behaves as on 0.3.0, and plan output for a Ladle repo stays as in 0.3.0 until it opts in with `adopt.mjs config --write --lane csf`.

### Added

- A third story lane, `stories.lane: "csf"`, for CSF story files read in place and never copied. A Vite plugin (`massimoStories`, in `scripts/lib/vite-stories.mjs`) builds the lane from a registry of the story files, computed at dev and build time and handed to the lane as the module `virtual:massimo-stories`. The canvas at `/stories/<slug>/<state>` renders one state per document, honours `mode=preview`, sets switch attributes on `<html>`, sets `data-story-ready`, and unmounts on `pagehide`. An old Ladle link, `/?story=<id>`, renders in place, and the lane mounts in `#ladle-root`, as Ladle does, so specs that wait on it keep working. The lane's `/meta.json` has Ladle's shape. The scaffold is the recipe `skills/stories/recipes/vite-csf.md`, and the stories skill routes an adopted Ladle repo there.
- `scripts/lib/ladle-ids.mjs`, so `stories.ids: "ladle"` keeps every id a Ladle repo already links to. It is ported from `@ladle/react` 5.1.1 (`lib/cli/vite-plugin/naming-utils.js`) and carries Ladle's MIT license and copyright notice in the file.
- New lane keys under `stories`: `ids`, `order`, `home`, `viewports`, `sideBySide`, `switchers`, `banners`, `frame`, `storyOnly`, `appCss`, `outDir`, `hostFiles`, `frozen` and `policy`. `reference/project.md` names each with its default.

- `stories.mjs`: `index` (the files, slugs and states per root; `--json` prints the registry), `--check` (a registry fault such as a duplicate id, a frozen file that changed, the graph's csf problems, a base CSS that holds `@source not`, app code that imports a module only stories use; these two CSS checks need `stories.appCss.base`) and `leak`, which compares the CSS of an app build and a lane build and refuses an output folder git does not ignore. The app holds a class only through the class's own rule, so a package's or a component library's selector that merely names it does not count. A word is read as Tailwind reads it, so a class a file outside the stories names after a selector's dot, in parentheses or before a comma counts as that file's. A class only the lane's own stylesheets give a rule is a leak in the app's CSS even where a test or a doc names it, since Tailwind makes no rule from a word it has no utility for. `check.mjs`, and so `ds:check`, runs `stories.mjs --check` after the graph when `stories.lane` is `csf`.

The patch changes only the specifier of each file's type import and, when a file keeps the tool's import (a frozen file), adds `src/stories/legacy-story-types.d.ts`, which declares the tool's module so its package can go. `convert stories` lists the frozen candidates, and `convert stories --freeze <file>` pins each one you confirm in `stories.frozen` by sha256, which `convert stories --check` and `stories.mjs --check` hold; `--refreeze <file>` pins one again after a change made on purpose. A frozen file's type import, and the declaration file the patch adds for it, are never listed as edits to make. The prose list leaves out the frozen files, which cannot change, and the files the recipe writes as they are, which name the tool on purpose.
- `adopt.mjs verify stories` on a csf lane compares the lane's ids, files, exports and merged meta with Ladle's own `meta.json` (`--against`), checks that every id the repo's specs, scripts, skills and docs use resolves, and with `--sweep <base url>` opens every state. `shoot.mjs --sweep` is the sweep itself (`--ready`, `--ids-from`, `--legacy`, `--routes`, `--workers`, `--timeout`, `--wait`); a state fails when it is never ready, holds no element, raises a page error, or sets `html[data-story-error]`, which the sweep reads again after `--wait` (500 ms in a sweep); `--sweep-baseline <file>` excuses a failure an earlier sweep also had, only when that sweep reached 98% ready. `--pairs` takes `--a-route` and `--b-route` to compare Ladle's routes with the lane's, and `shoot.mjs --pairs` takes `--workers <n>` to shoot that many pairs at once (one by default, as before), which `verify stories --pairs --shoot` passes on. `retire stories --dry-run` prints the edits still open for the story tool, and `--against <meta.json>` tells an id that was dead already from one the move loses.

## 0.3.0

Adopt the design-system setup a repo already has, instead of generating a second one beside it. massimo reads the repo's own story lane, header keys, graph, ratchet and token inventory through its config, runs beside them until both agree, then takes over one class at a time. After updating, run `init.mjs --update-scripts`. A project that sets none of the new keys gets the same graph, audit and token outputs as before.

### Added

- `/massimo:adopt` and `adopt.mjs`, for a repo with a setup of its own. `scan` lists what the repo already has (its story tools or lane, the `ds:` header keys it uses, its generated graph or index, its ratchet, token files and DESIGN.md, and the scripts that write them) and every file, package script and workflow that depends on each, without running any of it. `plan` writes a ledger (`<project>/adopt/ledger.json`) saying what becomes of each asset (keep, convert or retire) and what that loses, and a proposed config, which `config --write` merges in without overwriting a value you set. Each class (graph, stories, audit, tokens, docs) then moves one state at a time through found, mapped, shadowed, proven, cut-over and retired with `mark`. `verify` sets massimo's output beside the repo's own, class by class, and exits 1 on any difference you have not accepted with a reason (`accept`); an accepted difference opens again when it changes. `retire --dry-run` lists what retiring a class removes, everything that still depends on it, and any generator that stays and would write it again; the skill deletes only after a clean dry run and your OK. Each cut-over batch is one commit with an `Adopt-Batch` trailer, so one `git revert` undoes it.
- `detect` reports `adoptable` when a repo has a setup of its own, and `init` then adds the adopt phase. The phase is optional: a project made before 0.3.0 has it skipped, and STATUS.md and the session hook leave it out.
- `templates/design-system-shadow.yml`: a pull request workflow that runs `ds:check` and `adopt.mjs verify` beside the repo's own checks and never blocks a merge.
- `graph.keys` gives a repo's own `ds:` header keys a role massimo understands: `list`, `definitions` (custom properties a parent or a script sets, which the audit counts as defined), `scope` (one value per file, which audit exemptions can name) or `breakpoint` (a width and a reason).
- `graph.taxonomy` sets the tiers and groups a repo files its components under, path rules for files with no `ds:group` line, a parked marker, the keys each tier needs, and the tiers that are not live code. The graph reports a missing or misplaced group as a header fault, and `graph.strictFaults` makes faults fail the write and `--check`. `graph.kinds` adds node kinds such as layouts and pages, `graph.edges` reads imports in MDX files and `import.meta.glob` calls, and `graph.header: "top"` reads only the first comment block.
- A story lane with its own manifest: `stories.manifest`, `stories.pages` and `stories.frames` (with `stories.lane: "manifest"`) and `stories.componentless`. The graph takes each node's coverage from the manifest (a direct story, only an incidental one, or none) and writes the lane's problems to `graph.json`: a title outside the tiers, a missing page or frame, states that do not match, and a live component with no story.
- Audit settings for a repo's own rules. `audit.kinds` turns kinds off, or the Tailwind palette kind on, with the Tailwind config deciding which colours are the repo's own: a token called `red-600` that never reaches Tailwind leaves `text-red-600` counted. `audit.exempt` skips a kind by a scope's value, a tier or group, or a glob. `audit.arbitrary` and `audit.primitives` limit those kinds to colours, and `audit.failWhenBehind` fails `--check` while the baseline is behind the code. A new `breakpoint` kind holds `@media` widths and Tailwind screen variants to `tokens.breakpoints`. With a story manifest, the lane's four problems are audit kinds too. `audit.mjs --import <ratchet> --map <rule>=<kind>` seeds the baseline from a ratchet kept in another shape, once every mapped rule matches file by file.
- `check.mjs`, which `ds:check` now runs: every check that applies to the project, one line each, then the commands in `guard.extraChecks`.
- `tokens.mjs mirror` (with `tokens.mirror`) keeps a repo's style files as the source and writes the token set from them, with a value under any other selector kept as a scope and a declaration's comment as its description; `--check` fails while the mirror is behind the CSS. `tokens.mjs resolved` (with `tokens.inventory`) lists every custom property the sheets declare in `tokens/resolved.json`, with its file, layer, family and a resolved value per selector, plus the type classes, font faces and breakpoints.
- `shoot.mjs --pairs <file>` shoots pairs of URLs and exits 1 when a pair differs by more than `--max-diff`; a `dom` pair is compared by page text. `--playwright <path>` borrows Playwright from another checkout, and `--reduced-motion`, `--settle` and `--freeze` make shots repeatable.

### Changed

- `audits/baseline.json` becomes format 2 once it tracks a kind added in 0.3.0, such as `breakpoint` or the story kinds, and 0.2.1 refuses it by name. The new files (`tokens/resolved.json`, a pairs file, `adopt/inventory.json` and `adopt/ledger.json`) start at format 1.

## 0.2.1

Fixes to 0.2.0, a Figma library made by hand adopted rather than duplicated, and the format gates that let 0.3.0 change formats safely. After updating, run `init.mjs --update-scripts` so the project's copy, which CI runs, refuses files from newer versions.

### Fixed

- `tokens.mjs figma --record` decides the file allows one mode per collection (Figma's Starter plan) only when every collection in it has one mode. Before, a single one-mode collection was enough, so a missing Dark mode in a file that has two-mode collections went unreported.
- A Figma library made by hand is adopted, not duplicated. `tokens.mjs figma --record` and `--drift` pair code and Figma variables by the id recorded last time (same file, same type), then by name, then by the CSS variable a variable's code syntax names (`var(--c-ground)`). A pair made by code syntax keeps its own name and collection, its values are compared with references followed to the end, and the record's notes list each pair. A reference to a paired variable is compared in code's terms, so a rename in Figma or a hand-made name is not a difference. Variables are told apart by collection as well as name. Where several variables could pair, the first fitting one is paired and the rest are noted. New `tokens.mjs figma --pairs` lists the pairs and differences and writes nothing; the figma skill uses it before changing anything in Figma, and updates a paired variable instead of creating a second one. `tokens.mjs extract` reads each Figma variable's CSS variable from its code syntax. Mirrors recorded before 0.2.1 still read.
- CSS custom properties are read per member of a selector list, and per compound within a member. `html.dark, .inverse` and `[data-theme="dark"] body` set the dark theme. `html.dark .panel`, `.dark .card` and `:where(html.dark .panel)` reach into the page and are a component's scope, so they no longer replace the page's dark value. Nested selectors are read with their parent in place of `&`. Every `prefers-color-scheme` query is a theme (light the default, dark the dark), and a media query of only `screen` or `all` changes nothing. A root value under any other condition (a phone-width `@media`, a colour scheme with a width, `@supports`, a root variant such as `html[dir="rtl"]`) is an override, never the default; a property set only under a condition takes that value. The extract report says when a token is also set in a scope or under a condition, or only under one.
- `detect` recognises a story lane the repo already built: routes behind a `STORIES=1` flag or a separate stories config, and a stories folder with a manifest or an index (every recipe's index counts). The folder is the one the gate's scripts or config name; with several and none named, it lists them and guesses none. It reports the lane under `storyTools.lane` and suggests config that runs it: its pages as stories (or the `*.story.*` files when it has no pages folder, never its own frames), its dev script (never a build), and the port from `--port`, `-p` or `PORT=` (else the framework's default) with the URL. The lane is left out of the audit. The stories skill treats it as the lane and never scaffolds over it; before writing, it stops if a file the recipe creates already exists, and edits the framework's config rather than replacing it. Before, a repo whose own lane looked like massimo's recipe would have had it overwritten.
- Files from a newer massimo are refused by name instead of read as this version: a `massimo.config.json`, `graph.json` or `audits/baseline.json` in a newer format stops `graph`, `audit`, `docs` and `tokens`, and is never overwritten, with "update massimo: the plugin, then its init.mjs --update-scripts for the project's copy". A config can set `minScripts`, and older scripts then refuse it the same way. The hooks never fail on such a config: the agent guard still denies, and the session start says why the scripts cannot run. This is what lets the formats move in 0.3.0: 0.2.0 cannot be taught to refuse them, 0.2.1 can.
- `audit.mjs --lower` keeps the baseline of a kind it did not measure, skipped this run (no token set yet, no Tailwind) or unknown to these scripts, instead of dropping it, and `--check` names a kind it does not check.
- Run from the plugin, `graph`, `audit`, `docs` and `tokens` warn when the project's vendored scripts are older. `tokens.mjs migrate` still refuses then. The vendored version is read from its declaration in either quote style, and one that cannot be read neither warns nor blocks.

## 0.2.0

Extract a full design system from an existing repo, in the W3C Design Tokens format 2025.10. After updating, run `init.mjs --update-scripts`, rebuild the tokens once, and run `tokens.mjs migrate` when you want the new format.

### Added

- `/massimo:extract`: a full design system from an existing repo in one guided flow. Tokens for every family from what the repo already uses, each primitive's props, variants, states and usage rule, and a design-system README, approved family by family. It records progress against the graph, tokens and guard phases. `/massimo:start` offers it for a repo with styling but no token set.
- Readers for every place an existing repo keeps design values (`scripts/lib/readers.mjs`): CSS custom properties, now with `light-dark()` split into light and dark and RGB or HSL channel triplets (`236 229 209`, `210 40% 98%`) typed as colours that keep their channels as CSS; a Tailwind 3 config (`theme` and `theme.extend`, `DEFAULT` as `$root`, `rgb(var(--x) / <alpha-value>)` as a reference, font-size tuples as type steps); a CSS-in-JS or JS theme object (MUI, Chakra, Stitches, vanilla-extract and plain exports); Tokens Studio files; and Figma variables exported as JSON, from the REST API or from `read-library.js`. Custom properties go in families by the names systems use (`--space-*`, `--c-*`, `--dur-*`, `--z-*`), colours by their value, and a stem with a size and a line height, weight or tracking (`--h1-size`, `--h1-leading`) becomes a type step. `rgb(var(--x))` over a channel triplet is a reference that keeps its wrapper as CSS, `rgb(var(--x) / 0.14)` is the colour it makes in each theme, and a fluid `clamp()` size holds its largest value with the clamp kept. JavaScript is read as text by a small object-literal reader and never run, so a config reads without its packages installed; anything computed or spread is named in a note instead of guessed.
- The colour parser knows all 148 CSS named colours (24 before), computes `color-mix()` in sRGB, linear sRGB, OKLab and OKLCH, and reads `light-dark()`.
- The audit counts an inventory of the families a token set needs beyond its findings: line heights, letter spacing, font weights, shadows, borders, durations, easings, z-index and opacity, from CSS, JS style objects and Tailwind classes. It also says what each colour cluster is used for (background, text, border, fill, shadow). Neither joins the ratchet, so existing baselines do not move.
- `tokens.mjs extract` proposes a full token set from what the repo already uses. Its sources come first (CSS custom properties, `tokens.tailwindConfig`, `tokens.themeFiles`, `tokens.importFiles`, `tokens.figmaExport`, which `detect` now suggests), with `var(--x)` turned into references between them. Two names for one CSS variable (a Tailwind config's `base.100` and a stylesheet's `--color-base-100`) are one token, and a token whose name another source uses as a group takes its own variable's name, so nothing is lost. The audit then fills the gaps with values the code uses at least twice: colour ramps named by lightness, with in-between steps (`435`) when the nearest is taken, translucent colours as overlays named by their base (`black-12`, `blue-20`), shadow colours left in their shadows, and colours only ever found in data (an avatar palette) left out; semantic background, text and border colours from where colours are used, neutral first, with a coloured background as the accent; spacing on the detected grid, radii, font families, weights and sizes named around the body size, or by Tailwind's names in a Tailwind repo. Where the sources already define three or more steps of a scale, the code's other values are drift for the tidy phase, not new steps; typography composites (exact from a type step in a Tailwind config or a stylesheet, otherwise from the most used parts, with every assumption said; body text never takes `leading-none`, and a Tailwind size takes Tailwind's line height); shadows, borders, durations, easings, z-index and opacity. Every semantic token gets a drafted `$description`, and contrast pairs are marked by name (`base-content` on `base-100`, `content` on its group's `100`) or by role. `tokens/draft/report.md` lists each token with its value and where it came from, family by family, and each value it did not propose with the reason.
- The graph lists each component's props (TypeScript types, Vue's `defineProps`, Svelte 4 and 5 props, Astro `Props`, `cva` and `tv` variants) with values and defaults, how call sites set each one, and the states it styles (hover, focus, disabled, ARIA and data attributes, state props).
- New `docs.mjs` writes the design system's README for a person or an agent to read first, between `massimo:docs` markers so the team's own sections stay; `--check` joins `ds:check`.
- The graph and the audit read the token set in either format.

### Changed

- Tokens are written in the W3C Design Tokens format 2025.10. A resolver document (`tokens/tokens.resolver.json`, `"version": "2025.10"`) ties `base.tokens.json` to one file per theme (`theme/dark.tokens.json`); colours are colour objects in their own colour space, sizes and durations are `{ value, unit }`, typography, shadow, border, transition, gradient and stroke style are composites, and every token has an explicit or inherited `$type`, never a guess. massimo reads `$root`, `$extends`, `$ref` and `$deprecated`, keeps other tools' `$extensions`, and checks every value against its type. Each file it writes carries `$extensions.massimo.format: 2`, and a newer format or resolver version is refused with "update massimo". A `tokens.json` from before 0.2.0 still builds exactly as before.
- New `tokens.mjs migrate` converts a `tokens.json` from before 0.2.0 to 2025.10 (and `--to legacy` back), writes `migration-report.md` with anything that did not carry over exactly, checks that every output builds the same, and points the config at the new files. It refuses while the vendored scripts are older than it. A value the spec has no type for (`clamp()`, a grid template) moves to `$extensions.massimo.cssOnly` and still reaches the CSS outputs; a length in em keeps its exact CSS beside the nearest px value.
- `tokens.mjs extract` writes a 2025.10 draft in `tokens/draft/`, with a report of any value it typed or could not convert exactly.
- Contrast pairs name their use (`$extensions.massimo.contrast: { on, use }`), which sets the WCAG 2.2 minimum: text 4.5:1, large text 3:1, UI and focus 3:1. `tokens.mjs check` reports each failure under its theme. An old `on` plus `contrast` pair still works.
- Tailwind outputs map font weights, easings, `space`, `radii` and `$root` tokens; Tailwind 3 also gets durations, z-index and opacity. The JSON output carries `deprecated`.
- Figma: `figma-variables.json` gives every variable its scopes (by type and name; a colour ramp's steps hide once semantic colours exist, nothing is left on all scopes), durations in ms, and one font family per font variable. Typography tokens become text styles and shadow tokens effect styles, each field bound to the variable its part points at. Easings, transitions, gradients, borders and CSS-only values are listed under `notMirrored` instead of becoming strings.
- New `tokens.mjs figma --record <export.json>` and `--drift <export.json>`. The export is what `skills/figma/read-library.js` returns from one read-only `use_figma` call: every variable in every mode with aliases, and the text and effect styles. Recording checks the file against code, names each mismatch and writes `figma/mirror.json` with each variable's id and mirrored values. Drift compares code, the mirror and Figma, and writes `figma/drift.md` with each change put down to code, Figma or both. The hash now covers every file a resolver names.
- The figma skill uses that script instead of `get_variable_defs`, which reads one node and sees neither modes nor aliases. On a file that allows one mode per collection (Figma's Starter plan), it mirrors the default theme only and says the others stay in code. (`figma-create-new-file`, flagged in the review, is a real skill in Figma's plugin; it is now loaded before `create_new_file`.)
- New output format `designmd`: Google Labs' DESIGN.md for coding agents, pinned to format version alpha as published in release 0.4.0 (2026-07-27). The front matter holds the default theme's colours (references between colours kept), typography, radii and spacing; the prose holds descriptions, contrast pairs, shadows, and each component's `ds:use-when` and `ds:never` rules from the graph, in the order the spec sets. The format has no themes, so the file names the other themes and says they live in code. A colour DESIGN.md cannot read (`color()`, a `none` component) is written as its nearest sRGB hex and listed. Checked once with `@google/design.md` 0.4.0's linter: no errors.
- After updating, run `npm run ds:tokens` once and commit: every generated file has a new header, so `ds:check` reports them stale until rebuilt.
- `reviewer` and `visual-reviewer` declare `tools: Read, Grep, Glob, WebSearch, WebFetch`, so they cannot write or run commands. They no longer drive a browser: the ux skill captures each viewport and state (screenshots plus a page snapshot from the new `shoot.mjs --dom`) before it dispatches them.
- `ideator` declares `tools: Read, Grep, Glob, Write, WebSearch, WebFetch`, and a new PreToolUse hook (`scripts/agent-guard.mjs`) refuses its writes outside `<project>/explorations/`. The orchestrator now renders each direction and sends back broken ones.
