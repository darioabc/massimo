# Mockups and the canvas

How the `ideator` writes a round of directions, and how the `ux` skill shows them to the user. Mockups are plain HTML files in the repo, so they persist across sessions, diff in git, and open anywhere.

## Layout

```text
<project>/explorations/<topic>/
├── brief.md            topic brief and round log (owned by the ux skill)
├── round-1/
│   ├── Main.html       the lead direction
│   ├── Compact.html    one file per other direction, named for it
│   └── round.json      the round's metadata
├── round-2/ …
└── index.html          the canvas, generated by canvas.mjs
```

## A direction file

One whole surface per file. Self-contained apart from the kit:

```html
<!doctype html>
<html lang="en" data-theme="light">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Main: checkout summary</title>
  <link rel="stylesheet" href="../../../kit/kit.css">
  <style>
    /* direction styles: use var(--token) for every colour, space, radius, font */
  </style>
</head>
<body>
  <main class="surface"> … </main>
</body>
</html>
```

Rules:

1. **Link the kit.** `../../../kit/kit.css` resolves to `<project>/kit/kit.css`, the product's real tokens as CSS custom properties. If it does not exist yet, run `node <project>/scripts/tokens.mjs kit` first.
2. **Use the tokens.** Write `var(--color-…)`, `var(--spacing-…)` and friends, not literal values. This is what lets the translator map a mockup back to the system instead of transcribing hex.
3. **New values are labelled.** When a direction needs something the system lacks, define it in the file's `<style>` as a custom property with a `--new-` prefix and a one-line comment on its intent: `--new-color-highlight: #fff4d6; /* soft callout fill for promo rows */`. The translator formalises or maps it.
4. **Real content.** Use the real record the orchestrator passed, verbatim.
5. **Fixed frame.** Size the root to the target viewport (`width: 1280px` for desktop, `375px` for mobile) and record it in `round.json`. The canvas scales frames to fit.
6. **Both themes when the product has both.** Respect `data-theme` through the kit's tokens; do not hard-code one theme's colours.
7. **Fonts.** Use the kit's font tokens. If the product loads web fonts, add the same `<link>` the product uses.
8. **Static is fine.** Show states side by side (default, hover, empty, error) inside the frame rather than scripting interactions. A small script is allowed when an interaction is the point of the direction: set `"scripts": true` on that direction in `round.json`. The canvas frames every mockup in a sandbox, and only a direction marked this way runs its script, in a frame the theme switch cannot reach.
9. **No app chrome you were not asked for.** Reproduce the real surrounding chrome when the baseline has it; do not invent navigation, toolbars or browser frames.

## round.json

```json
{
  "round": 1,
  "framing": "Make the order summary scannable on mobile without hiding fees",
  "baseline": "<project>/explorations/checkout-summary/round-1/Main.html",
  "directions": [
    {
      "file": "Main.html",
      "title": "Stacked totals",
      "rationale": "Totals first, line items collapsed, the pattern Stripe Checkout and Shopify use",
      "scope": "component",
      "changed": "new direction",
      "width": 375,
      "height": 812
    }
  ],
  "verdict": null
}
```

`baseline` is the canonical baseline's repo-relative path for follow-up rounds (null in round 1 of an ideate arc). `scope` is one of `copy-only`, `component`, `breakpoint`, `new route`, `larger build`. The ux skill fills `verdict` after the user decides: `{ "decision": "lock" | "seed" | "none" | "stop", "pick": "Main.html", "feedback": "…" }`.

## Showing a round

The `ux` skill (never a worker) shows the round:

1. `node <project>/scripts/canvas.mjs <project>/explorations/<topic>` builds `index.html`: rounds newest first, each direction in a scaled frame with its title, rationale and scope, earlier rounds marked with their verdict.
2. Serve the project folder: `node <project>/scripts/serve.mjs` (default port 4700). Run it in the background.
3. Show it with whatever the host offers, in this order:
   - a browser pane or preview tool → open `http://localhost:4700/explorations/<topic>/`;
   - an artifact or page-publishing tool → build a single file with `canvas.mjs … --inline` and publish `index.inline.html` (it inlines the kit and every direction);
   - an inline HTML widget tool → render each direction's HTML inline;
   - otherwise give the user the URL, and on macOS offer `open <url>`.
4. Then the synthesis and the decision prompt (see the ux skill).

Use one canvas per topic for the whole loop, so the user keeps one URL.
